Wallet in this browser

Keys never leave this device. The blockchain is not downloaded: walletd in WebAssembly asks a node only for the data the wallet needs.

Slow: the phrase does not say when the wallet was created, so the whole chain since the amethyst upgrade (≈1.9 million blocks) is scanned. This takes an hour or more and downloads about 2–3 GB (use Wi-Fi), and on a phone the screen must stay on. If you have a backup file, restore from it instead: it remembers the creation date and finishes much faster.

24 BIP39 words (amethyst wallet). The words are always English, whatever the interface language.

Optional: when was the wallet created? Scanning then starts from that date. If unsure, pick an earlier date: payments received before it will not be found.

The .amwbackup file saved under “Security”, or the .wallet file of a desktop wallet (amethyst type, address starting with bcnZ), and its password. They usually remember the creation date, so restoring takes seconds.

A desktop wallet that was itself restored from its phrase keeps no creation date. For such a file, enter when the wallet was first created (if unsure, an earlier date), or the whole chain is scanned.

Security

The file holds the recovery phrase, encrypted with a separate password (not the PIN), and the state of the synced wallet, so restoring from it scans only from the first payment. Keep the file and the password apart.

Node

searching…

The node sees which blocks and transactions the wallet requests and your IP address, but not your keys. node.bytecoin.community is run by the Bytecoin community; node01/node02 are run by the original Bytecoin developers. All three allow CORS, so they work directly from the browser. node01/node02 do not share their pool of unconfirmed transactions: through them an incoming payment appears once it is in a block (≈2 min).
